uds: ISO 14229 (Unified Diagnostic Services) in pure Racket🔗ℹ

turinglambdaai <turinglambdaai@users.noreply.github.com>

 (require uds) package: uds

This package implements the message layer of ISO 14229-1 — UDS (Unified Diagnostic Services), the application protocol spoken by automotive ECUs over ISO-TP (isotp) or DoIP. It covers service identifiers, negative response codes, diagnostic trouble codes, and request/response construction and parsing.

The library is transport-agnostic and pure: builders return the payload bytes of one ISO-TP message and parsers consume them; timing, transport and security-algorithm concerns stay with the caller. There is no FFI and no system dependency.

1 Quick start🔗ℹ

(require uds)
 
 
(diagnostic-session-control 'extended)
 
 
(read-data-by-identifier '(61840))
 
 
(response-parse #"P\3\0002\0\310")
(session-control-response (positive-response-data (response-parse #"P\3\0002\0\310")))

2 Service identifiers🔗ℹ

The sid:* bindings name every ISO 14229-1 service (sid:diagnostic-session-control, sid:read-data-by-identifier, …). service-name maps an ID back to a symbol, and service-uses-sub-function? tells whether the service’s second byte is a sub-function — the distinction that drives generic framing.

4 Diagnostic trouble codes🔗ℹ

struct

(struct dtc (number status-byte))

  number : (integer-in 0 65535)
  status-byte : (integer-in 0 255)
One trouble code: a 16-bit number and a status byte. The number’s text form ("P0123") maps through dtc-text->number / dtc-number->text: bits 15–14 encode the system letter (P/C/B/U), bits 13–12 the first digit, and the remaining three digits occupy one BCD nibble each. parse-dtc-records reads the 3-byte record runs of ReadDTCInformation responses.

(struct dtc-status (test-failed
    test-failed-this-operation-cycle
    pending
    confirmed
    test-not-completed-since-last-clear
    test-failed-since-last-clear
    test-not-completed-this-operation-cycle
    warning-indicator-requested))
  test-failed : boolean?
  test-failed-this-operation-cycle : boolean?
  pending : boolean?
  confirmed : boolean?
  test-not-completed-since-last-clear : boolean?
  test-failed-since-last-clear : boolean?
  test-not-completed-this-operation-cycle : boolean?
  warning-indicator-requested : boolean?
The status byte (ISO 14229-1 Annex D) as flags; make-dtc-status, dtc-status->byte and byte->dtc-status convert. +dtc-group-all+ (0xFFFFFF) is the "all DTCs" group for ClearDiagnosticInformation.

6 Responses🔗ℹ

procedure

(response-parse payload)

 → (or/c positive-response? negative-response?)
  payload : bytes?
Classifies one response payload: bytes starting with 7F become a negative-response; everything else must be a positive response (SID | 0x40) and is split into echoed sub-function (for sub-function services) and the response record.

struct

(struct positive-response (sid sub-function data))

  sid : (integer-in 0 255)
  sub-function : (or/c #f (integer-in 0 127))

7 Caveats🔗ℹ

  • Authentication (SID 0x29) framing is included in the service table but no typed builder yet; use make-request.

  • Security algorithms (seed/key) are ECU-specific by design and stay with the caller.

  • The library does not manage sessions, timing (P2/P2*) or retransmission; pair it with isotp for the transport layer.
